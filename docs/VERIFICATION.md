## Требует проверки на самом NAS

Локальные service hooks и static ELF не являются эмуляцией Package Center
или подтверждением совместимости с конкретным ядром/ACL DSM. На NAS нужно:

1. Проверить прекращение доступа после выхода из DSM и отказ обычному
   пользователю на реальном NAS. Установка и вход администратора уже проверены ниже.
2. Выделить внутреннему пользователю `plex-helper` Read/Write только для
   тестовой общей папки и проверить отказ без прав.
3. Проверить значок в главном меню DSM. Open из Package Center и HTTPS
   через встроенный nginx proxy уже проверены; внешнего порта службы нет.
4. Проверить автозапуск после reboot и остановку долгой операции/восстановление
   журнала. Run/Stop на свободной службе уже проверены.
5. Повторить scan → выбор метаданных → preview → apply → undo на маленьких
   тестовых видео, с симлинком, конфликтом и изменённым после Apply файлом.
6. Проверить разные тома, права новых файлов для Plex и фактический fsync на
   выбранных файловых системах. Не копируются ACL/xattr/sparse-layout.
7. Установить обновлённый SPK с большим build number, убедиться в сохранении
   настроек и журналов; заранее сделать копию pkgvar.
8. Измерить RAM/CPU на J4125/4GB. GOMEMLIMIT256MiB — мягкая цель Go, а не
   измеренное потребление памяти или гарантия максимального RSS.

## Диагностика установщика DSM 14 октября 2026

На реальном NAS через браузер воспроизведена ошибка версии 0.1.0-1:
после чтения SPK загрузчик `DialogVueBundle.js` выбрасывает `Cannot read
properties of undefined (reading 'name')`, затем мастер показывает
сообщение об отсутствии тома. Сам DSM показывает исправный Том 1,
10,8 ТБ, свободно 4,9 ТБ. Никакие тома или данные не изменялись.

Мастер передавал объект компонента напрямую в JSONP callback. Официальный
[пример Synology](https://github.com/SynologyOpenSource/ExamplePackages/blob/main/ExamplePackage/WIZARD_UIFILES/src/remove-entry.js)
использует `export default`, а его webpack config экспортирует namespace
модуля через JSONP. В версии 0.1.0-2 добавлено поле `default` и проверка
этого контракта; локальные package/service/reproducibility tests прошли.
Повторная загрузка 0.1.0-2 на этом NAS подтвердила исчезновение сообщения
об отсутствии тома: мастер отображает `Plex Helper login` и поле пароля,
кнопка «Далее» заблокирована при пустом пароле. Новых ошибок загрузчика
после исправления нет. Установка, запуск и DSM ACL ещё не проверены;
создание пароля передано пользователю. Установку приложения ещё не запускали.


## Переход на DSM-сессию (0.1.1-3)

По запросу пользователя отдельный пароль удалён из NAS-пакета,
JSONP-мастер больше не включается в SPK. Local/development mode сохраняет
собственную авторизацию; пакет всегда запускает `--auth dsm` и отвергает
публичный bind. Настройки и журналы сохраняются, старые пароли на NAS
не дают доступ к API. Нативный web-config worker регистрирует прокси
DSM → loopback, адрес приложения и ресурсы поддерживают prefix.

### Диагностика интерфейса DSM

Штатный ELF authenticate.cgi (12386 байт) прочитан с NAS по SSH;
SHA256 `fe5cbb0e7f19645b42c1aa180774887f93ba83ae529fb79cc3b0dfd533298278`.
REA open_binary подтвердил ELF64/x86_64 и идентичность файла. Нативная
декомпиляция REA недоступна: Ghidra/IDA не настроены, Hopper отсутствует.
Локальный LLVM objdump отдельно показал вызов штатной проверки SynoCgiIsAuthorized;
это обычное статическое исследование, не REA Evidence и не наблюдение исполнения.
Бинарник не включён в пакет или репозиторий. Реальный успешный вход подтверждён
браузером после передачи SynoToken, а не только статическим анализом.

## Групповое распознавание и предпросмотр (0.2.0-1)

Изменён сценарий: «Подготовить» сканирует папку, ищет названия по группам,
выбирает однозначные результаты и автоматически открывает предпросмотр.
Ручной результат поиска применяется ко всей группе без подтверждения каждой
серии. Подготовленные операции выбраны по умолчанию, финальное изменение
файлов происходит только по кнопке «Переименовать».

Локально проверено:
- HTTP Scan → Prepare → Match → Plan → Apply → Undo на пяти искусственных
  эпизодах и одном связанном субтитре; источники существуют до Apply.
- Один поиск + карточка сериала + один запрос сезона вместо пяти повторений.
- Оригинальное английское название и локализованное русское название TMDB.
- Неоднозначные одинаковые названия не выбираются автоматически; год отделяет
  одноимённые сериалы; разные provider ID и фильмы не смешиваются.
- Ручная замена общего названия/ID сохраняет координаты каждой серии и ранее
  исправленные номера. Неизвестная серия остаётся для проверки.
- Защита Prepare сессией/CSRF, отказ при устаревшем скане.
- Браузер и настоящий TMDB: пять искусственных The.Idol.S01E01…E05 распознаны
  как «Кумир (2023)», tmdb135251, подготовлены названия всех эпизодов и субтитра.
- Браузер: повторный поиск и выбор результата применяются сразу к пяти файлам.
- Браузер: исключение E05 сохраняется при обновлении предпросмотра; Apply
  переносит четыре эпизода и субтитр, E05 остаётся на месте; Undo возвращает
  все перемещённые файлы. Проверены фактические пути на диске.
- `go test -race ./...`, `go vet ./...`, `node --check`,
  `scripts/test-package.py` (static ELF, lifecycle, reproducibility).

На NAS отдельно проверен DSM ACL внутреннего пользователя plex-helper:
«Чтение/Запись» на /volume1/video; приложение читает video и movie.
Реальные файлы не перемещались/переименовывались. На NAS установлено обновление 0.2.0-1 через Package Center. Сохранены
настроенные пользователем исходная папка /volume1/video/serial, папка назначения
и токен TMDB (токен не читался и не выводился). DSM-вход продолжает работать.
Кнопка «Подготовить» на реальной папке The.Idol.S01.2160p.MAX.WEB-DL.DV.HDR.H265
выбрала «Кумир (2023)» для всех пяти серий и создала общий предпросмотр.
Все пять операций выбраны; Apply не запускался. Apply/Undo с DSM ACL на NAS
по-прежнему требует отдельной тестовой медиатеки.
