# Plex Helper для Synology

Это самостоятельный пакет `.spk` с веб-интерфейсом. Один серверный исполняемый файл Go содержит интерфейс и все серверные зависимости. На NAS не нужны Java, Python, Go, Node.js, Docker или Container Manager. Медиатека обрабатывается на NAS; компьютер нужен только для браузера либо для самостоятельной сборки пакета.

Целевая конфигурация: DS920+, Intel J4125, 4 ГБ RAM, DSM 7.3.2-86009 Update 4. По [официальной таблице CPU Synology](https://kb.synology.com/en-global/DSM/tutorial/What_kind_of_CPU_does_my_NAS_have) DS920+ относится к `Geminilake`, `x86_64`; [таблица архитектур пакетов](https://help.synology.com/developer-guide/appendix/platarchs.html) допускает семейство `x86_64` для Geminilake. INFO устанавливает нижнюю границу DSM `7.2-72806` (7.2.2), поскольку мастер использует описанный для 7.2.2 формат. Это целевая совместимость, а не результат установки на вашем NAS.

## Установка

1. Скопируйте готовый `dist/plex-helper-x86_64-0.1.0-2.spk` на устройство, с которого открываете DSM. При необходимости проверьте `.spk.sha256`.
2. В DSM откройте **Package Center → Manual Install**, выберите `.spk` и следуйте мастеру. DSM предупредит об установке стороннего пакета. Пакет не подписан Synology; он работает с правами внутреннего пользователя пакета.
3. В мастере задайте отдельный пароль Plex Helper длиной от 12 символов. Имя пользователя приложения — **admin**. Пароль DSM сюда вводить не нужно. Передача пароля идет через stdin при установке; в командной строке и журнале его нет. Формат мастера описан в [Synology WIZARD_UIFILES 7.2.2](https://help.synology.com/developer-guide/synology_package/wizard/WIZARD_UIFILES_v2.html). Его отображение в DSM 7.3.2 ещё необходимо проверить на NAS.
4. Запустите пакет. Откройте **Plex Helper** в главном меню DSM или **Open** в Package Center. По умолчанию открывается `http://NAS:8650/` в браузере, с отдельной авторизацией приложения. Установленное приложение работает без компьютера и без подключенного к нему диска.
5. Если мастер не показал поле пароля, приложение запускается в режиме защищенной первой настройки. Администратор один раз читает код через SSH: `sudo cat /var/packages/plex-helper/var/setup-token`. Введите этот код и новый пароль в странице первой настройки. После инициализации файл с кодом удаляется. Код не следует публиковать и передавать другим пользователям. Если ошибка мастера мешает самой установке, не считайте установку проверенной: сохраните сообщение DSM для исправления пакета.
6. На первом запуске работайте только с отдельной тестовой общей папкой, например `/volume1/plex-helper-test`. Создайте в ней входящие файлы и выходную библиотеку. Реальную медиатеку пока не добавляйте.

## Права на медиапапки

Пакет запускается от системного внутреннего пользователя **plex-helper**, заданного через [conf/privilege](https://help.synology.com/developer-guide/privilege/privilege_config.html). Скрипты не запускают сервер от root, не создают пользователей вручную, не применяют `chmod 777` и не меняют ACL автоматически.

В DSM: **Control Panel → Shared Folder → выбрать тестовую папку → Edit → Permissions → System internal user → plex-helper → Read/Write → Save**. Для переименования необходима запись как в родительские папки источников, так и в папки назначения. Права только чтения достаточны для сканирования, но не для применения изменений. Для Plex Media Server отдельно оставьте его собственные права чтения. Такой путь настройки внутреннего пользователя подтвержден в [инструкции Synology для медиапапок Plex](https://kb.synology.com/en-us/DSM/tutorial/How_to_transfer_video_files_from_Video_Station_to_Plex_Media_Server).

Если конкретные существующие файлы не наследуют разрешения общей папки, настройте наследуемый ACL для нужной тестовой подпапки через **File Station → Properties → Permission**; проверьте действие для файлов и дочерних папок. Описание этих средств есть в [File Station Permissions](https://kb.synology.com/index.php/en-us/DSM/help/FileStation/privilege?version=7). Выбор папки в приложении задаёт область работы; доступ дополнительно ограничивается ACL DSM. Приложение не может само выдать себе право на любую папку.

## Сеть и HTTPS

По умолчанию сервер слушает TCP 8650 на интерфейсах NAS. Пакет регистрирует сервис **Plex Helper** для выбора в firewall DSM через [port-config resource](https://help.synology.com/developer-guide/resource_acquisition/port_config.html). Это регистрация порта, а не автоматическое разрешение в firewall или публикация в интернете. При включенном firewall разрешите сервис только из нужной локальной сети. [Описание .sc](https://help.synology.com/developer-guide/integrate_dsm/ports.html) объясняет регистрацию сервиса.

Для HTTPS используйте DSM **Control Panel → Login Portal → Advanced → Reverse Proxy**: источник `https://plex-helper.<ваш-домен>:443`, назначение `http://127.0.0.1:8650`. Назначьте сертификат DSM для выбранного домена и открывайте HTTPS URL напрямую. В `var/service-listen` можно записать одну строку `127.0.0.1:8650`, затем перезапустить пакет; обычный значок DSM всё ещё ведет на HTTP8650, поэтому при loopback используйте свой HTTPS URL/закладку. Настройка обратного прокси на DSM ещё требует проверки на NAS.

Сервер поддерживает собственный TLS: поместите в `var/service-tls-cert` и `var/service-tls-key` по одной строке с абсолютным путем к соответствующим PEM-файлам. Оба файла должны быть доступны пользователю `plex-helper`; используйте отдельные копии сертификатов в защищенной папке, а не расширяйте доступ к системным ключам DSM. После перезапуска сервер использует HTTPS на настроенном порту. Тогда открывайте `https://NAS:8650/` напрямую: ярлык DSM по умолчанию остаётся HTTP. Не меняйте эти файлы, если используете обратный прокси с HTTP backend. Файлы с путем нужно завершать переводом строки.

Авторизация Plex Helper независима от DSM. Видимость значка для администраторов DSM не является защитой HTTP-сервера; все API изменения медиатеки требуют входа в приложение. Сессии после перезапуска сбрасываются. Токен TMDB пользователь предоставляет в настройках самостоятельно; ключи FileBot не используются. Для поиска метаданных нужны DNS и исходящий HTTPS с NAS к TMDB; TLS использует системное хранилище доверенных сертификатов DSM. Это сетевое подключение и доверие сертификатам также нужно проверить на NAS; установка пакета от доступа к TMDB не зависит.

## Запуск, остановка, обновление и данные

Используйте **Package Center → Plex Helper → Run / Stop**. Стандартный [start-stop-status](https://help.synology.com/developer-guide/synology_package/scripts.html) управляет процессом и сообщает DSM его состояние; DSM вызывает его при загрузке/выключении. Скрипт проверяет принадлежность PID нужному бинарнику и внутреннему пользователю. Остановка посылает SIGTERM и дает до 30 секунд на завершение, без принудительного SIGKILL. Если остановка не завершилась, смотрите журнал и не выключайте NAS во время файловой операции.

Настройки, хэш пароля, журнал операций и служебные данные находятся в **`/var/packages/plex-helper/var`** (`SYNOPKG_PKGVAR`). Для установки на volume DSM отображает его в `/volumeN/@appdata/plex-helper`. Исполняемый файл и ярлык находятся в `target`; DSM заменяет только этот payload при обновлении. [FHS Synology](https://help.synology.com/developer-guide/integrate_dsm/fhs.html) определяет `var` как постоянное хранилище. Сервисный журнал: `var/service.log`, предыдущий: `var/service.log.previous` (ротация на старте, если старый журнал превышает 1 MiB).

Обновление: остановите активные файловые операции, сделайте резервную копию `var`, установите `.spk` с большим номером версии через **Manual Install**. DSM останавливает старый пакет и перезапускает ранее работающий пакет; пароль при обновлении не сбрасывается. Скрипты обновления и удаления не удаляют `var` и не затрагивают медиапапки. При повторной установке с сохранившимся `config.json` пароль из мастера игнорируется: используйте прежний пароль; если предыдущая первая настройка не завершена, используйте код первой настройки. Постоянное сохранение после реального удаления/повторной установки соответствует FHS, но пока не проверено на DSM 7.3.2. Перед удалением сохраните копию состояния: без журнала отмена старых операций недоступна. Не удаляйте каталог состояния вручную как часть обычного обновления.

`GOMAXPROCS=2`, `GOMEMLIMIT=256MiB` задаются сервисом для небольшого NAS. Значение памяти — мягкая цель Go runtime, не гарантия максимального RSS; измерения потребления на DS920+ пока нет. Транскодирование, индексирование Plex и загрузка всей медиатеки в память не выполняются.

## Воспроизводимая сборка

На машине сборки нужны Go **1.25.14**, Python **3.12** и `make` (либо прямой вызов Python). Для `make package-test` также нужен Node.js 18+; `NODE=/путь/к/node` выбирает исполняемый файл проверки мастера. Node.js не требуется для сборки SPK или запуска на NAS. Никакие зависимости не скачиваются при установке или запуске на NAS. Версия Go подтверждена в [официальных release notes](https://go.dev/doc/devel/release#go1.25.14). Совместимость с фактическим ядром DSM ещё проверяется запуском на NAS; отсутствие динамического загрузчика проверяет builder.

```sh
git clone https://github.com/damuraiz/plex-helper.git
cd plex-helper
make test
make package-test
make spk
```

Заранее установите Go 1.25.14 с [официальной страницы загрузок](https://go.dev/dl/); builder использует `GOTOOLCHAIN=local` и отклоняет другую версию, ничего не скачивая автоматически. При необходимости передайте `GO=/путь/к/go`; для offline сборки обеспечьте доступный локальный кэш. В Go проекте нет сторонних модулей. Проверка воспроизводимости выполняет два полных build в одном окружении и сравнивает `.spk` побайтово. Для сверки между машинами используйте одинаковые версии Go, Python/zlib и исходников.

```sh
SOURCE_DATE_EPOCH=1791936000 python3 scripts/build-spk.py --version 0.1.0-2
sha256sum dist/plex-helper-x86_64-0.1.0-2.spk
```

На macOS вместо `sha256sum` можно использовать `shasum -a 256`. Builder закрепляет `CGO_ENABLED=0`, `GOOS=linux`, `GOARCH=amd64`, `GOAMD64=v1`, `-trimpath`, `-buildvcs=false`, `-ldflags='-s -w -buildid='`; фиксирует порядок tar, владельцев, права, timestamps и gzip timestamp. Пакет содержит статический ELF64 x86-64, JSON DSM ресурсов, жизненный цикл, мастер и оригинальные значки. Builder отказывается упаковывать macOS/Mach-O или ELF с `PT_INTERP`. Уже собранный бинарник можно передать как `--binary /путь/к/linux-amd64/plex-helper`. Параметр `--version` меняет номер пакета; runtime версию задают исходники приложения.

GitHub workflow `.github/workflows/build.yml` выполняет проверки и сохраняет SPK как artifact. [Запуск 38596356709](https://github.com/damuraiz/plex-helper/actions/runs/38596356709) успешно выполнил тесты и сборку на Ubuntu 24.04, Go1.25.14/Python3.12. Этот запуск относится к версии 0.1.0-1. Версия 0.1.0-2 пересобрана локально с исправлением JSONP-экспорта мастера; результаты CI для неё следует проверять отдельно. Проверки Linux не заменяют установку на DSM.

## Что проверено и что требуется на NAS

`scripts/test-package.py` проверяет два полных одинаковых build, безопасные пути архива, права и INFO, наличие статического ELF и ресурсов DSM; собирает локальный бинарник приложения; запускает и останавливает его в временном каталоге; проверяет HTTP, повторный Start, мёртвый и чужой PID, сохранение конфигурации в upgrade/uninstall hooks и минимальную длину пароля. Все файловые проверки проекта работают с временной тестовой медиатекой. Эти проверки не эмулируют DSM.

На **DS920+ / DSM 7.3.2-86009 Update 4** ещё нужно проверить:

- Manual Install, предупреждение стороннего пакета, отображение мастера и вход с заданным паролем (либо защищенная первая настройка по коду).
- Значок главного меню, Open в Package Center, порт firewall и обратный прокси HTTPS.
- Фактическое создание внутреннего пользователя, права ACL тестовой общей папки и ошибки при отсутствии прав.
- Run/Stop, автозапуск после перезагрузки, прекращение долгой операции и журнал.
- Применение/отмена на небольшой тестовой медиатеке; проверка неизменности файлов, конфликта назначения, изменения файла после переименования.
- Установка обновления с большим номером версии и сохранение настроек/журнала; удаление/повторная установка с резервной копией.
- Потребление CPU/RAM на небольшой и большой тестовой выборке; поведение разных томов и файловых систем.

До успешного прогона этого списка пакет является подготовленной к проверке первой версией. Настоящую библиотеку эта разработка не изменяла.
