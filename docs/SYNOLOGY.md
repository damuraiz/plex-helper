# Plex Helper для Synology

Самостоятельный нативный пакет `.spk` для **DS920+, Intel J4125, 4 ГБ RAM,
DSM 7.3.2-86009 Update 4**. Статический Go-сервер включает веб-интерфейс.
На NAS не нужны Docker, Container Manager, Java, Python, Node.js или Go.
Файлы обрабатываются на самом NAS. Минимальная версия в INFO — DSM 7.2.2.

## Установка и вход

1. Выберите `dist/plex-helper-x86_64-0.3.0-1.spk` в
   **Package Center → Manual Install**. Контрольная сумма лежит рядом.
2. Примите предупреждение DSM о стороннем пакете и подтвердите установку.
   Пакет не подписан Synology и работает от внутреннего пользователя пакета.
   Мастера пароля, аккаунта `admin` приложения и кода первой настройки нет.
3. Войдите в DSM учётной записью из группы **administrators**. Откройте
   **Plex Helper** из меню DSM или кнопкой Open в Package Center.
   Приложение использует этот вход; дополнительный пароль не нужен.
4. Используйте сначала отдельную тестовую общую папку,
   например `/volume1/plex-helper-test/incoming` и `/volume1/plex-helper-test/library`.
   Настоящую медиатеку пока не добавляйте.

Приложение открывается на том же адресе, порту и протоколе, что DSM:
`https://NAS:5001/webman/3rdparty/plex-helper/`. Пользовательский домен и
HTTPS DSM сохраняются; при другом порте DSM используется его текущий адрес.
Внутренний сервер слушает **127.0.0.1:8650**. Этот порт не публикуется в
сеть и не требует firewall rule. Внешний вход выполняется через nginx DSM.

## Как проверяется доступ

Страница получает штатный CSRF-токен текущей DSM-сессии из `webman/login.cgi`
и передаёт его через заголовок X-Syno-Token. Этот интерфейс описан в
[официальном Calendar API Guide, стр. 5](https://global.download.synology.com/download/Document/Software/DeveloperGuide/Package/Calendar/All/enu/Calendar_API_Guide_enu.pdf).
Токен существует только в памяти страницы, не помещается в URL, настройки
или browser storage. Пароль DSM приложению не передаётся.

На каждом API-запросе приложение запускает штатный
[authenticate.cgi Synology](https://help.synology.com/developer-guide/integrate_dsm/web_authentication.html)
с CGI-параметрами сессии DSM. Cookie передаётся только локальному системному
проверяющему процессу и не записывается в настройки или журнал. Пользователь
должен входить в группу administrators. Истёкшая сессия, выход из DSM,
обычный пользователь или отказ проверяющего процесса закрывают доступ.
Проверка Origin и отдельный CSRF-токен защищают операции записи.
Независимого аккаунта, пароля или срока действия входа приложения на NAS нет.

Прокси регистрируется штатным
[web-config resource worker](https://help.synology.com/developer-guide/resource_acquisition/web_config.html).
Пакет объявляет собственный location внутри DSM, не переписывает глобальные
конфиги nginx. DSM проверяет конфигурацию и управляет её подключением.
Установка/остановка/запуск пакета могут вызвать reload nginx DSM;
сам сервер приложения не запускается от root. Web Station не требуется.
На DS920+ / DSM 7.3.2-86009 Update 4 проверены работа helper, определение
администратора damuraiz, nginx proxy и открытие кнопкой Open в Package Center.

## Права на папки

DSM → **Панель управления → Общая папка → Разрешения → Внутренний пользователь
системы → plex-helper**. Выдайте Read/Write только тестовой общей папке.
В File Station → Свойства → Разрешения проверьте наследование ACL для подпапок.
Не используйте `chmod 777`. Вход администратора DSM не повышает права службы:
операции выполняет внутренний пользователь **plex-helper**, созданный через
[conf/privilege](https://help.synology.com/developer-guide/privilege/privilege_config.html).

Папки без прав возвращают ошибку. Plex должен иметь доступ на чтение к
результатам отдельно. При переносе между томами создаётся staged copy:
ACL, xattr и sparse-layout не копируются, поэтому наследуемые ACL и доступ
Plex нужно проверить на небольшой тестовой выборке.

## Служба, обновление и данные

Run/Stop в Package Center управляют `start-stop-status`; lifecycle включает
защиту от чужого/повторно использованного PID и повторного запуска.
DSM управляет автозапуском. Run/Stop и повторный DSM-вход проверены на NAS.
Перезагрузка NAS ещё не проверена.
Служба завершает текущие запросы по SIGTERM; если операция длится больше
30 секунд, stop сообщает ошибку и не применяет SIGKILL.

Конфигурация, токен TMDB и журналы хранятся в
`/var/packages/plex-helper/var` (SYNOPKG_PKGVAR, постоянный @appdata).
Обновляйте SPK с большим номером версии, предварительно сохранив копию var.
Hooks не удаляют настройки или медиатеку. Старые passwordHash/passwordSalt,
если были созданы предыдущей версией, не используются в DSM-режиме;
вход через старый пароль и setup-token отключён. Данные других настроек
и журналов сохраняются. Сохранение после реального удаления/повторной
установки требуется проверить на DSM: перед удалением сохраните var.

`GOMAXPROCS=2`, `GOMEMLIMIT=256MiB` — ограничение параллельности и мягкая цель
Go runtime. Это не измеренный предел RSS. Один замер после открытия интерфейса на DS920+: RSS 7480 КиБ (около 7,3 МиБ),
UID процесса 253128, внутренний bind 127.0.0.1:8650. Это замер в покое,
а не предел памяти или оценка больших файловых задач.

## Воспроизводимая сборка

На машине разработки нужны Go **1.25.14**, Python **3.12** и make.
В проекте нет сторонних Go-модулей. Builder использует GOTOOLCHAIN=local,
не скачивает зависимости и отклоняет другую версию Go.

```sh
git clone https://github.com/damuraiz/plex-helper.git
cd plex-helper
make test
make package-test
make spk
```

При необходимости передайте `GO=/путь/к/go`, `PYTHON=/путь/к/python3.12`.
На macOS Go установлен в `/opt/homebrew/bin/go`.

```sh
SOURCE_DATE_EPOCH=1791936000 python3 scripts/build-spk.py --version 0.3.0-1
sha256sum dist/plex-helper-x86_64-0.3.0-1.spk
```

На macOS используйте `shasum -a 256`. Фиксируются CGO_ENABLED=0, GOOS=linux,
GOARCH=amd64, GOAMD64=v1, trimpath, buildvcs=false, buildid, порядок tar,
владельцы, права, timestamps и gzip timestamp. Builder проверяет ELF64 и
отсутствие PT_INTERP. Для сверки между машинами нужны одинаковые исходники,
Go и Python/zlib. Node.js больше не нужен даже для package tests.

## Проверка

Локально проверены статическая упаковка, две побайтово одинаковые сборки,
реальный запуск/остановка службы, сохранение настроек и тесты файловых операций.
Тесты DSM проверяют фактический запуск подменного CGI-процесса, окружение,
CSRF, отказ неадминистратору, истечение сессии и отсутствие отдельного пароля.
Они не заменяют проверку штатного authenticate.cgi на NAS.

На реальном NAS проверены Manual Install, обновления до 0.1.1-3, работающий
сервер, Run/Stop и Open без второго входа (DSM: damuraiz), loopback-only bind и HTTP 401
при обращении к API без DSM-сессии. Console приложения без ошибок.
Ещё нужны отказ обычному пользователю и после выхода из DSM, ACL медиапапок,
reboot, обновление с сохранением непустых настроек и журналов,
тестовая цепочка scan → preview → apply → undo.
Подробный список и история проверки: [VERIFICATION.md](VERIFICATION.md).
Настоящая библиотека этой разработкой не изменялась.

Linux CI 0.1.1-3: [успешный запуск](https://github.com/damuraiz/plex-helper/actions/runs/38607186900). Артефакт CI совпал побайтово с установленным на NAS SPK.
